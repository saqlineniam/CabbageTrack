# 4. Detectors

The tracker needs a segmentation detector whose class 1 is the plant. The paper uses three YOLOv9c-seg models
(Ultralytics), all in `data/weights/`:

| file | used on | trained on | test plant P / R | test mask AP50 |
|---|---|---|---|---|
| `cabbage.pt` | Field A, held-out flight | 103 Field A + 25 held-out-flight frames (COCO start) | 97.8 / 97.8 % | 98.3 % |
| `young_cabbage.pt` | Field B | 37 frames of Field B's first clip (fine-tuned from `cabbage.pt`) | 99.2 / 97.5 % | 98.9 % |
| `cauliflower.pt` | Field C | 43 frames of a sister flight over the Field C crop (fine-tuned from `cabbage.pt`) | 95.2 / 90.7 % | 95.3 % |

Classes: 0 Aisle, 1 plant (Cabbage / Cauliflower), 2 Divider, 3 Drain. P / R = mask precision / recall at confidence
0.5 and IoU 0.5; AP from pycocotools; full-resolution masks (`detector/evaluate.py`, `detector/evaluate_adapted.py`).
All numbers: `data/detector/README_numbers.md` (regenerated by `python paper/detector_numbers.py`).

**Held out for re-identification, not for detection.** The cabbage detector's annotated images include 47 frames of
the held-out flight (25 training, 7 validation, 7 test, 8 unused); 314 of the flight's 374 plant identities appear in
at least one training image. The held-out flight tests the re-identification model, whose design and settings were
fixed on Fields A-C. Field B's detector was trained on Field B's own first clip.

## 4.1 Data (`data/detector/<detector>/`)

| folder | content |
|---|---|
| `roboflow/` | every annotated image with its original annotation (`images/`, `ann/`) and `manifest.csv`, downloaded read-only from Roboflow |
| `split/` | the YOLO-seg dataset used for training: `train/` (x3 augmented), `val/`, `test/`, `data.yaml`, COCO ground truth per split, `split_manifest.csv` (source video, frame, split of every image) |
| `source_check.csv` | (young cabbage, cauliflower) which video each annotated image comes from (whole-image correlation) |
| `training/` | (fine-tuned detectors) Ultralytics `args.yaml` and `results.csv` |
| `cabbage/benchmark/` | the six-model benchmark (Table 1): every run's settings, training curve and weights, evaluation, statistics |

**Splits.** Frames are split in contiguous time blocks, not at random, so validation and test frames are not
near-copies of training frames. Cabbage: per video 20 blocks, 3 to test, 3 to validation, 14 to training; training
frames within 1 s of a validation / test frame are dropped (`detector/build_cabbage.py`). Young cabbage and
cauliflower: 15 blocks, blocks 1, 6, 11 to validation, 3, 8, 13 to test (`build_young.py`, `build_cauliflower.py`);
test scores are also given for test frames at least 1 s from every training frame.

**Augmentation.** Each training image plus 2 copies with random flips, crop 0-20 %, rotation +-15 deg, brightness
+-20 %, blur 0-2 px (`detector/augment.py`, the original Roboflow x3 recipe); validation and test images are not
augmented. Training also uses Ultralytics' on-the-fly augmentation (mosaic, flips, colour, shift, scale).

## 4.2 Train

All detectors: input 640 px, batch 8, optimiser auto (AdamW), early stopping with patience 50, best epoch by
validation fitness, seed 2 (the benchmark: seeds 0, 1, 2).

```bat
:: Table 1 benchmark: 6 models x 3 seeds (about 12-15 h on an RTX 4060); Mask R-CNN needs detectron2 in third_party\detectron2
python detector\train_queue.py
python detector\train_detectron2.py --help
python detector\evaluate.py
python detector\summarize.py
python detector\stats.py

:: fine-tuned detectors (start from data\weights\cabbage.pt)
python detector\build_young.py --train --evaluate
python detector\build_cauliflower.py --train --evaluate
python detector\evaluate_adapted.py outputs\detector\adapted_detectors_table1_protocol.csv
```

Training runs go to `outputs/detector/`. GPU training is not bit-for-bit deterministic across machines; the
published weights are the ones the paper used (SHA-1 in `data/SHA1SUMS.txt`).

Rebuilding a split (`build_cabbage.py`, `build_young.py`, `build_cauliflower.py` without `--train`) rewrites
`data/detector/<detector>/split/` from `roboflow/`; the cabbage build traces every image to its video frame and needs
`data/videos/fieldA.mp4` and `heldout.mp4`.

## 4.3 Re-download from Roboflow (optional)

The record already holds the downloads. To fetch them again (read-only; needs access to the Roboflow workspace):

```bat
set ROBOFLOW_API_KEY=<your key>
python detector\fetch_roboflow.py --project drone-shot --out data\detector\cabbage\roboflow
```

The key is read from the environment and never written to a file.

## 4.4 Your own crop

Annotate frames from flights of the new crop (not from the flight you want to test), fine-tune from `cabbage.pt` as
`build_young.py` does, and keep the plant as class 1. The tracker itself needs no change.
